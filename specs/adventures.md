# adventures Spec（ユーザー管理機能）  

作成者：ブタメロン  
作成日：2026/6/20  

# ■ ディレクトリ  

adventures ユーザー管理モジュール  

# ■ 目的  

ギルドメンバーの管理を行うモジュール

主な用途  

- アプリケーションユーザー管理  

# ■ 機能概要  

- 初回ユーザー設定機能
- ユーザープロフィール編集機能  

# ■ 関連テーブル一覧  

- users // 認証基盤
- adventurer // 公開アプリケーションユーザーテーブル  
- adventurer_setting //　ユーザー設定テーブル
- user_identity // 本人情報 公開初期では作成しません
- adventures_abilities //　職業、スキルタグ中間テーブル。スキル毎の経験値もここに保持
- abilities // 職業、スキルタグ一覧


# ■ モジュール概要  

- ユーザーの初回設定およびユーザー編集を行う
- ユーザーは初回ログイン時、強制的に設定を求められる。（anonymousは存在しない）
- adventuresはauth.idの他、不変のvertual_nameを保持する。
- ユーザーの職業を初回設定およびユーザー編集で追加可能
- 未登録の場合は未登録となる。
- adventuresはauth.idの他、不変のvertual_nameを保持する。

※初期値はインフルエンスを初期職業として保持する。(いいねで経験値が向上！)

# ■ skills table specs
- 親skill,子skillを明確に分離する。
- UX上の成約として、親、子まで。孫は持たない（今後拡張の可能性あり。）
- 階層NOを保持する。親：１,子：２として、分岐する。（今後拡張する場合は孫：３を準備する）

# jobs・skills Spec（職業、スキル管理機能）  

作成者：ブタメロン  
作成日：2026/6/20  

# ■ ディレクトリ  

jobs 職業管理モジュール  

# ■ 目的  

ギルドメンバーの職業管理を行うモジュール

主な用途  

- 職業管理機能。スキルと職業は別の概念である。  
- 職業とスキルの関係は、職業の下にスキルがぶら下がる形が理想。
- 例えば、ITエンジニアならその下にpythonのようなスキルセットがぶら下がる。
- スキルと職業はユーザーでは増やすことはできない仕様
- 申請画面はないが、その他職業やその他スキル設定機能を保持し、  
　上位登録の場合は運営が追加する。（厳密には、日次バッチで複数人登録者が存在する場合）

# ■ 機能概要  

- 職業の追加、更新、削除機能。Administratorのみ表示。
- skillsの追加、更新、削除機能。Administratorのみ表示。
- 職業追加に関するspecsタグ
- プロフィール画面で職業を追加することができる。
- 検索条件として利用
- 1ユーザーは複数職業を保持できる。
- 1ユーザーは複数スキルを保持できる。

## その他項目
- 自由入力内容は運営分析用として保存する。
- 一定人数以上が同一内容を登録した場合、正式な職業・スキルとして採用を検討する。
- 集計は日次バッチで実施する。
- 現時点ではユーザーからの申請画面は設けない。

# ■ ランクの仕様 

##  jobsの経験値、レベル、jobランク
 経験値、レベル、ランクは連動する。  
 経験値←掲示板でいいね機能の他に経験値セット機能を保持。
 レベル←経験値量を人が判断しやすくするツール。
 
 jobランク←レベルの優位性をより人が判断しやすくするツール。

　職業の経験値←スキル経験値の合計

# ■ ユーザー名の下
 ユーザー名の下に、小さい文字で職業とランクを固定表示可能とする。
 
 例：
 　ブタメロン
 　ITエンジニア lankB (称号)

スキルレベルを管理する場合は、mid_users_skills にレベル情報を保持することを想定する。
